# Contest Logic & Architecture (30-Day Contributor Challenge)

This document explains the architecture and business logic for the ED-Library Contributor Challenge.

## Overview

The 30-Day Contributor Challenge is a gamified event where approved contributors compete to earn points daily. The maximum score per contributor is **100 points per day**. 

The points are distributed across three categories:
1. **Acquisition (A)**: Bringing in new users (Max 50 points/day).
2. **Engagement (E)**: Activity generated by the contributor's referrals (Max 40 points/day).
3. **Content (C)**: Uploading high-quality documents and courses (Max 10 points/day).

## Enrollment Flow

1. **Eligibility**: The user must be signed in and possess an approved (`status === 'live'`) Contributor profile.
2. **Contest Page (`app/contest/page.tsx`)**: 
   - If not signed in: Prompts the user to sign up or log in.
   - If not a contributor: Prompts the user to apply for a contributor account (`/onboarding/step-1`).
   - If eligible: The user sees an Enrollment Modal, agrees to the terms, and clicks "Join the Arena".
3. **Backend Action**: 
   - `editContributorService` updates the contributor document, setting `joinedContest: true` and `joinedContestAt: ISOString`.
   - `initContestPerformance` is called automatically (in `contributors.service.ts`) to create the initial tracking document for this user in the `contest_performance` collection.

## Scoring System

### 1. Acquisition (A)
- **Formula**: `New Users × 5 points`
- **Max Cap**: 50 points (10 users/day).
- **Tracking**: Tracked using the `sources` collection when a user signs up using a referral link `?ref=[contributorId]`.

### 2. Engagement (E)
- **Formula**: `(Active Referrals × 2) + (Referral Downloads × 1)`
- **Max Cap**: 40 points.
- **Note**: Engagement tracking logic is the next immediate feature to be built.

### 3. Content (C)
- **Formula**: `(Documents Uploaded × 5) + (Courses Created × 10)`
- **Max Cap**: 10 points (e.g., 2 documents or 1 course per day).

## Relevant Services & Files

### `lib/services/contest_performance.service.ts`
Manages the `contest_performance` collection in Appwrite.
- Tracks `acquisitionScore`, `engagementScore`, `contentScore`, and `totalScore` for each contributor.
- Exposes `updateContestScoresService` to recalculate and persist points.

### `app/admin/contest-scoring/page.tsx`
Admin dashboard for manually reviewing and updating contest scores for each participant. Allows admins to search contributors, see their current scores, and save overrides or updates.

### `lib/services/sources.service.ts`
Handles tracking for acquisition. If a URL contains `?ref=xxx` or `?mref=xxx`, this service logs click counts, sign-up counts, and contributor conversion counts for the referral ID.
